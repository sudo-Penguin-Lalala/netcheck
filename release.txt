# NetCheck v1.2.0

## Security
- Decouple `AUTH_TOKEN` from private-target SSRF gate. New `ALLOW_PRIVATE_TARGETS` env
  controls RFC1918 / loopback scans explicitly. Legacy "AUTH_TOKEN implies allow"
  preserved for one release with a deprecation warning; removed in v2.0.
- New `TRUSTED_PROXIES` env replaces `--forwarded-allow-ips=*`. Default
  `127.0.0.1,172.16.0.0/12` honors XFF only from loopback nginx + Docker bridge.
  Blocks rate-limit-bypass via forged `X-Forwarded-For` from arbitrary peers.
- `/api/whois` raw-socket fallback now resolves the IANA `refer:` target and
  refuses TCP-43 if it lands in private/loopback/link-local/multicast/reserved
  space. Closes a referral-driven SSRF pivot through a hostile TLD.
- `/api/whois` raw-socket fallback caps responses at 512 KB. Hostile registry
  can no longer exhaust process memory via an unbounded stream.
- `/api/headers` no longer reflects `Authorization`, `Cookie`, or
  `Proxy-Authorization` headers back to the client.
- `/api/dns` now validates hostnames against private/loopback targets before
  resolution. Closes SSRF via DNS query to internal domains.
- `/api/rdns` now validates IPs against private/loopback targets before reverse
  lookup. Closes SSRF via reverse DNS query to internal IPs.
- `is_private_target_blocked()` no longer mutates `socket.setdefaulttimeout`
  process-global state. Concurrent requests no longer race on the timeout.

## Added
- `SECURITY.md` with deployment matrix (8 topology cases), trust-boundary
  reference, migration notes, and hardening checklist.
- `.env.example` documents `ALLOW_PRIVATE_TARGETS` and `TRUSTED_PROXIES`.

## Changed
- Dockerfile `CMD` uses shell-form so `TRUSTED_PROXIES` env expands at runtime.
- Validators emit a deprecation log line (once per process) when legacy
  AUTH_TOKEN→private-allow compatibility kicks in.

## Migration
Existing deploys with `AUTH_TOKEN` set: behavior unchanged. To silence the
deprecation warning and survive v2.0, add to `.env`:
```
ALLOW_PRIVATE_TARGETS=1
TRUSTED_PROXIES=127.0.0.1   # or your reverse-proxy CIDR
```
